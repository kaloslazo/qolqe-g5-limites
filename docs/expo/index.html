1 · Herramienta

Un solo runner para la API y la web

Enfoque

Playwright Test trae su propio cliente HTTP (request). Con playwright-bdd, cada .feature de Gherkin se convierte en un test de Playwright.

Primero lo implementamos con pytest-bdd. Lo cambiamos para usar una sola herramienta en las tres partes del proyecto.

Por qué la elegimos

  • Un solo runner para la API y la web
  • Ejecuta Gherkin: el caso de negocio es el test
  • Levanta la app antes de probar (webServer)
  • Deja reporte HTML y JUnit para el CI

1 · Herramienta

Cada paso del escenario es una función

features/limites.feature

@HU-G5-02 @apiScenario Outline: Nuevo límiteGiven que inicié sesión como AnaWhen cambio mi límite diario a S/ <limite>Then el resultado es "<resultado>"Examples:  | limite | resultado       |  | 50     | LIMITE_INVALIDO |

tests/api-playwright/pasos.ts

When(  'cambio mi límite diario a S\\/ {word}',  async ({ sesion }, limite) => {    sesion.respuesta =      await sesion.api('put',        '/api/limites',        { limite_diario: limite });});

bddgen genera un test por fila de Examples; al correr, cada frase busca su función y esta llama a la API.

1 · Herramienta

Ventajas, limitaciones y capacidades de IA

Ventajas

  • Un runner para API y web
  • Levanta la app con webServer
  • Reportes HTML, JUnit y trazas
  • TypeScript con autocompletado

Limitaciones

  • Una BD y un reloj: corre en serie
  • Gherkin necesita el paso bddgen
  • No valida el contrato OpenAPI
  • Requiere Node además de Python

IA (desde la 1.56)

  • Planner explora la app y escribe el plan
  • Generator escribe las pruebas
  • Healer repara las que fallan
  • Riesgo: el Healer puede «arreglar» la prueba que detecta un defecto

2 · Módulo

El límite acota lo que puede salir en un día

Si alguien obtiene el celular y el PIN, el límite acota la pérdida. Las alertas avisan al cliente cuando su gasto del día llega al umbral que fijó.

Límite diario

  • R-G5-01 · De S/ 100 a S/ 2,000, en múltiplos de 50
  • R-G5-02 · Bajarlo rige al instante y cancela el aumento pendiente; subirlo rige a las 24 horas
  • RN-06 · Cuentan las transferencias Qolqe e interbancarias

Alertas de consumo

  • R-G5-03 · Hasta 5, umbral de S/ 10 a S/ 2,000 en múltiplos de 10
  • R-G5-04 · TRANSFERENCIAS y TODAS no superan el límite vigente
  • HU-G5-08 · Un SMS por día al alcanzar el umbral

3 · Diseño de casos

Schemathesis prueba el contrato OpenAPI

Lee /openapi.json y genera cientos de solicitudes. Comprueba que ninguna respuesta sea 500 y que cada respuesta esté documentada y cumpla su esquema.

Una corrida: 518 solicitudes sobre 13 operaciones. Deja un reporte HTML en reportes/schemathesis/.

AvisoLectura
Rechazó una solicitud válida según el esquemaReglas de negocio que el OpenAPI no declara: múltiplos de 50, saldo, duplicados
Aceptó una solicitud que viola el esquemacci de otro tipo se ignora; pin fuera de patrón en el login. Severidad baja
Cabecera Allow inválidaLas respuestas 405 a OPTIONS no la incluyen. Severidad baja

Recomendación: declarar multipleOf, mínimos y máximos en el contrato.

Cierre

Tres defectos críticos tocan el dinero

Las interbancarias no cuentan para el límite diario, el saldo puede quedar negativo y se puede transferir a una cuenta cerrada. Con ellos abiertos, Qolqe no debería salir a producción.
